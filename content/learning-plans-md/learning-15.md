# 第一部分：计算机网络（30 题）

## 一、TCP（必背，10 题）

### 1. TCP 三次握手 ⭐⭐⭐（必背！）
```
客户端              服务端
  │ ─── SYN(seq=x) ─────→ │     [客户端 → SYN_SENT]
  │ ←── SYN+ACK(seq=y) ── │     [服务端 → SYN_RCVD]
  │ ─── ACK(ack=y+1) ───→ │     [双方 → ESTABLISHED]
```

**为什么三次不是两次** ⭐⭐⭐：
1. **防止旧 SYN 包**建立无效连接（半连接堆积）
2. **同步双方初始序列号**（双向都要确认）
3. 第二次只能确认客户端发送能力，第三次才能确认服务端

### 2. TCP 四次挥手 ⭐⭐⭐（必背！）
```
客户端              服务端
  │ ─── FIN ──────────→ │     [客户端 → FIN_WAIT_1]
  │ ←── ACK ─────────── │     [服务端 → CLOSE_WAIT, 客户端 → FIN_WAIT_2]
  │ ←── FIN ─────────── │     [服务端 → LAST_ACK]
  │ ─── ACK ──────────→ │     [客户端 → TIME_WAIT → 2MSL → CLOSED]
```

**为什么四次不是三次**：
- 服务端收到 FIN 后可能还有数据要发，所以 ACK 和 FIN 分开发
- 全双工 → 两个方向独立关闭

### 3. TIME_WAIT 状态 ⭐⭐⭐
- **谁有**：**主动关闭**的一方
- **等多久**：**2MSL**（Maximum Segment Lifetime，Linux 默认 60s）
- **为什么**：
  1. 确保最后的 ACK 能到达对端（对端没收到会重传 FIN）
  2. 让本次连接的旧数据包在网络中消亡，避免污染新连接

### 4. 大量 TIME_WAIT 怎么办
- 调小 `tcp_fin_timeout`
- 开启 `tcp_tw_reuse`（复用 TIME_WAIT 端口）
- 短连接改长连接

### 5. SYN 洪水攻击
- 攻击者大量发 SYN 不回 ACK → 占满半连接队列
- 解决：**SYN Cookie**（不分配资源，把状态编码在 ACK 中）

### 6. TCP vs UDP ⭐⭐⭐
| | TCP | UDP |
|---|---|---|
| 连接 | 面向连接 | 无连接 |
| 可靠 | 可靠（ACK+重传）| 不可靠 |
| 顺序 | 保证 | 不保证 |
| 拥塞控制 | 有 | 无 |
| 速度 | 慢 | 快 |
| 适用 | HTTP、文件传输 | DNS、视频、游戏 |

### 7. TCP 可靠传输怎么保证 ⭐⭐⭐
1. **校验和**：检测数据完整性
2. **序号 + ACK**：保证顺序、不丢失
3. **超时重传**
4. **流量控制**（滑动窗口）
5. **拥塞控制**（慢启动、拥塞避免、快重传、快恢复）

### 8. 流量控制 vs 拥塞控制 ⭐
- **流量控制**：防止发送方发太快**接收方**处理不过来（滑动窗口）
- **拥塞控制**：防止发送方发太快**网络**承受不住（拥塞窗口）

### 9. 拥塞控制四算法 ⭐
1. **慢启动**：cwnd 指数增长（1→2→4→8）
2. **拥塞避免**：到阈值后线性增长
3. **快重传**：收到 3 个重复 ACK 立即重传
4. **快恢复**：阈值减半，cwnd = 阈值，继续线性增

### 10. 粘包 / 拆包 ⭐
- **现象**：TCP 是字节流，多个应用层消息可能粘在一起或被拆开
- **解决**：
  1. 固定长度
  2. 分隔符
  3. **消息头中包含长度字段**（最常用）

## 二、HTTP / HTTPS（10 题）

### 1. HTTP 报文结构 ⭐
```
请求行：GET /path HTTP/1.1
请求头：Host: xxx.com
       Content-Type: ...
（空行）
请求体：{...}
```

### 2. HTTP 状态码 ⭐⭐⭐
| 范围 | 含义 | 常见 |
|---|---|---|
| 1xx | 信息 | 100 Continue |
| 2xx | 成功 | 200 OK、201 Created、204 No Content |
| 3xx | 重定向 | **301 永久**、**302 临时**、304 Not Modified |
| 4xx | 客户端错误 | 400、**401 未认证**、**403 禁止**、**404 不存在** |
| 5xx | 服务端错误 | **500**、502 Bad Gateway、503 Service Unavailable、504 Gateway Timeout |

### 3. 502 vs 504 ⭐
- **502 Bad Gateway**：网关收到上游**错误响应**（后端服务挂了或返回异常）
- **504 Gateway Timeout**：网关等上游**超时**（后端服务慢，没在时间内响应）

### 4. GET vs POST ⭐⭐⭐
| | GET | POST |
|---|---|---|
| 参数 | URL | 请求体 |
| 长度限制 | URL 长度限制 | 无 |
| 缓存 | ✅ | ❌ |
| 幂等 | ✅ | ❌ |
| 安全 | URL 暴露参数 | 较好（仍非加密） |
| 历史 | 浏览器历史保留 | 不保留 |

**幂等性**：多次请求结果相同。GET / PUT / DELETE 幂等，POST / PATCH 不幂等。

### 5. HTTP 1.0 / 1.1 / 2.0 / 3.0 ⭐
| | 1.0 | 1.1 | 2.0 | 3.0 |
|---|---|---|---|---|
| 连接 | 短连接 | **长连接默认** | 长连接 | QUIC |
| 多路复用 | ❌ | ❌ | ✅ | ✅ |
| 协议头 | 文本 | 文本 | **二进制** | 二进制 |
| 头压缩 | ❌ | ❌ | HPACK | QPACK |
| 底层 | TCP | TCP | TCP | **UDP（QUIC）** |

### 6. HTTPS 加密流程 ⭐⭐⭐
```
1. 客户端 → 服务端：发送支持的加密套件 + 随机数 1
2. 服务端 → 客户端：选定套件 + 随机数 2 + 证书（含公钥）
3. 客户端验证证书 → 生成随机数 3（预主密钥）→ 用公钥加密发送
4. 双方根据 3 个随机数算出对称密钥
5. 后续用对称密钥加密通信
```

**核心**：**非对称加密交换密钥** + **对称加密传输数据**（性能权衡）。

### 7. HTTP vs HTTPS ⭐⭐⭐
| | HTTP | HTTPS |
|---|---|---|
| 加密 | ❌ 明文 | ✅ TLS |
| 端口 | 80 | 443 |
| 证书 | 不需要 | 需要 CA 证书 |
| 速度 | 快 | 略慢（多握手） |

### 8. 数字证书作用
- 证明服务端身份（防中间人攻击）
- CA 用私钥签名 → 客户端用 CA 公钥验签

### 9. HTTPS 解决了什么
- **窃听**：加密传输
- **篡改**：完整性校验
- **冒充**：证书认证

### 10. HTTP 长连接 / 短连接
- **短连接**：每次请求都建立 TCP（HTTP 1.0 默认）
- **长连接**：`Connection: keep-alive`（HTTP 1.1 默认），复用 TCP
- **优势**：减少握手开销

## 三、网络分层与其他（6 题）

### 1. OSI 七层 vs TCP/IP 四层 ⭐⭐
| OSI 七层 | TCP/IP 四层 | 协议 |
|---|---|---|
| 应用层 / 表示层 / 会话层 | **应用层** | HTTP / FTP / DNS |
| 传输层 | **传输层** | TCP / UDP |
| 网络层 | **网络层** | IP / ICMP |
| 数据链路层 / 物理层 | **网络接口层** | 以太网 |

### 2. 一个 URL 输入到看到页面的完整过程 ⭐⭐⭐（必背！）
1. **URL 解析**
2. **DNS 解析**（浏览器缓存→OS→hosts→DNS服务器递归查询）
3. **TCP 三次握手**
4. **TLS 握手**（HTTPS 才有）
5. **发送 HTTP 请求**
6. **服务器处理 + 返回响应**
7. **浏览器解析渲染**（HTML→DOM、CSS→CSSOM、JS 执行）
8. **TCP 四次挥手**

### 3. DNS 解析过程 ⭐
1. 浏览器缓存 → 系统缓存 → hosts 文件
2. **本地 DNS 服务器**（运营商）
3. **根域名服务器** `.`
4. **顶级域名服务器** `.com`
5. **权威域名服务器** `xxx.com`
6. 返回 IP

**DNS 用 UDP 也用 TCP**：查询用 UDP，**主从同步用 TCP**。

### 4. ARP 协议
- **IP 转 MAC 地址**
- 局域网内广播：谁是 IP=xxx 的，告诉我你的 MAC

### 5. WebSocket vs HTTP ⭐
| | HTTP | WebSocket |
|---|---|---|
| 连接 | 短/长 | 长连接 |
| 通信 | 半双工（请求-响应） | **全双工** |
| 服务端推送 | ❌（除非 SSE） | ✅ |
| 适用 | 普通 Web | 实时聊天、推送 |

### 6. WebSocket 建立过程
1. HTTP 发起带 `Upgrade: websocket` 的请求
2. 服务端响应 101 Switching Protocols
3. 升级为 WebSocket 协议（基于 TCP）

## 四、Cookie / Session / Token（4 题）

### 1. Cookie vs Session ⭐⭐⭐
| | Cookie | Session |
|---|---|---|
| 存储 | 客户端 | **服务端** |
| 安全 | 低（用户可改） | 高 |
| 容量 | 4KB | 大 |
| 跨域 | 默认不带 | 通过 cookie 关联 |

### 2. Session 怎么工作
1. 客户端登录，服务端创建 Session 存到内存/Redis
2. 服务端返回 SessionID（通过 Cookie）
3. 客户端后续请求带 Cookie，服务端用 SessionID 查 Session

### 3. JWT vs Session ⭐⭐⭐（你简历有 JWT！）
| | JWT | Session |
|---|---|---|
| 存储 | 客户端 | 服务端 |
| 扩展性 | 无状态，**易水平扩展** | 需共享（Redis） |
| 失效 | 难（需 Redis 黑名单） | 易（删 session） |
| 体积 | 大 | 小 |

### 4. JWT 组成
- **Header.Payload.Signature**
- Header：算法 + 类型
- Payload：业务数据（**Base64 可解码，别放敏感数据**）
- Signature：HMAC(Header+Payload, 密钥)

# 第二部分：操作系统（25 题）

## 一、进程与线程（8 题）

### 1. 进程 vs 线程 ⭐⭐⭐
| | 进程 | 线程 |
|---|---|---|
| 定义 | 资源分配最小单位 | CPU 调度最小单位 |
| 内存 | 独立 | **共享进程内存** |
| 切换开销 | 大 | 小 |
| 通信 | IPC（管道/消息队列/共享内存） | 直接访问共享内存 |

### 2. 进程的 5 种状态
```
创建 → 就绪 → 运行 → 阻塞 → 终止
       ↑__________ ↓
```

### 3. 进程间通信 IPC 方式 ⭐
1. **管道**（pipe）：单向，父子进程
2. **命名管道**（FIFO）：双向，任意进程
3. **信号量**（semaphore）：同步互斥
4. **消息队列**：消息传递
5. **共享内存**（最快）：多进程共享一段内存
6. **Socket**：跨主机通信

### 4. 线程间通信
- 共享变量（需要锁）
- wait/notify
- 阻塞队列
- ThreadLocal（不算"通信"是隔离）

### 5. fork() 系统调用 ⭐
- 创建子进程
- 父子进程**共享代码段，独立的数据段、堆、栈**
- 子进程拷贝父进程的资源（**写时复制**优化）

### 6. 写时复制 Copy On Write ⭐⭐⭐
- **fork 后父子共享物理页**（只读）
- 谁要写时才复制一份独立的页
- 优势：fork 极快、节省内存
- **Redis 的 RDB 就用这个**

### 7. 用户态 vs 内核态
- **用户态**：受限执行（不能直接访问硬件、不能执行特权指令）
- **内核态**：完全权限
- **切换**：通过**系统调用 / 中断 / 异常**
- 切换开销大，所以减少系统调用是性能优化方向

### 8. 协程是什么
- **用户态轻量线程**，不需要内核切换
- 协作式调度（主动 yield）
- 切换开销极小（不用陷入内核）
- Java 21 有虚拟线程（Virtual Thread）

## 二、内存管理（6 题）

### 1. 虚拟内存 ⭐⭐⭐
- 每个进程有**独立的虚拟地址空间**（如 64 位下理论 256TB）
- 通过**页表**映射到物理内存
- 优势：进程隔离、超过物理内存（用 swap）

### 2. 分页 vs 分段
- **分页**：固定大小（通常 4KB），方便管理
- **分段**：按逻辑（代码段/数据段/堆/栈）划分
- **现代 OS**：段页式（分段在分页之上）

### 3. 页表 + TLB ⭐
- **页表**：虚拟页号 → 物理页号
- 多级页表（节省空间）
- **TLB**：硬件缓存页表项（加速地址转换）

### 4. 缺页中断
- 访问的页不在物理内存 → 触发缺页中断
- OS 从磁盘 swap 把页换入
- 慢！要避免大量缺页

### 5. 内存分配 brk vs mmap ⭐
- **brk**：调整堆顶指针，**小块内存**（< 128KB）
- **mmap**：映射文件到内存或匿名映射，**大块内存**
- Java 用的是这两个的封装

### 6. 内存泄漏 vs 内存溢出
- **泄漏 Leak**：用完没释放，慢慢累积
- **溢出 OOM**：申请不到足够内存
- 泄漏的终点是溢出

## 三、IO 模型（核心，5 题）

### 1. 5 种 IO 模型 ⭐⭐⭐
1. **阻塞 IO（BIO）**：调用 read 阻塞直到数据来
2. **非阻塞 IO（NIO）**：read 立即返回，没数据返回错误，需轮询
3. **IO 多路复用**：一个线程监听多个 fd（**select / poll / epoll**）
4. **信号驱动 IO**：数据到了发信号通知
5. **异步 IO（AIO）**：内核完成所有操作后通知应用（真正的异步）

### 2. select / poll / epoll ⭐⭐⭐（必背）
| | select | poll | epoll |
|---|---|---|---|
| 最大连接 | 1024 | 无限 | 无限 |
| 数据结构 | bitmap | 数组 | 红黑树 + 就绪链表 |
| 找就绪 fd | **O(n) 遍历** | O(n) 遍历 | **O(1)** 直接拿 |
| 拷贝 | 每次全拷 | 每次全拷 | 只拷就绪 |
| 触发模式 | LT | LT | **LT + ET** |

### 3. epoll 工作流程
```c
epoll_create()  // 创建实例
epoll_ctl()     // 注册/删除 fd
epoll_wait()    // 阻塞等待，返回就绪 fd 列表
```

### 4. LT vs ET ⭐
- **LT 水平触发**（默认）：只要 fd 有数据可读就一直通知
- **ET 边沿触发**：从无到有才通知一次，必须一次读完
- ET 性能更高但编程更难

### 5. Java NIO 对应
- Java NIO Selector → Linux epoll
- Netty 基于 NIO，所有高性能 Java 服务器（Tomcat/Redis 客户端 Lettuce）都用

## 四、文件 / 死锁 / 调度（6 题）

### 1. 死锁四大必要条件 ⭐⭐⭐
1. **互斥**：资源独占
2. **占有并等待**：持有锁同时请求新锁
3. **不可剥夺**：锁不能强制释放
4. **循环等待**：锁形成环

**破坏任一即可避免**，常用**按固定顺序加锁**。

### 2. 进程调度算法
- **FCFS**：先来先服务
- **SJF**：短作业优先
- **优先级**
- **时间片轮转**
- **多级反馈队列**（实际 OS 用的）

### 3. 零拷贝 ⭐⭐⭐
**传统**：磁盘 → 内核缓冲区 → 用户缓冲区 → socket 缓冲区 → 网卡（**4 次拷贝**）
**零拷贝**：磁盘 → 内核缓冲区 → 网卡（**用 sendfile 跳过用户态**）

**用途**：
- Kafka 高吞吐
- Nginx 静态文件
- Java 的 FileChannel.transferTo

### 4. mmap 和零拷贝
- mmap 把文件映射到用户空间 → 用户态可直接读，不用 read 系统调用拷贝
- 也是一种"零拷贝"

### 5. 缓冲区 PageCache
- OS 把磁盘数据缓存到内存
- 后续读不用真的访问磁盘
- **Redis、Kafka 都受益于 PageCache**

### 6. 中断
- **硬件中断**：键盘、网卡通知 CPU
- **软中断**：系统调用、异常
- 中断处理过程会保存上下文 → 执行处理 → 恢复

## 二、数据结构速查

### 1. 数组 vs 链表 ⭐
| | 数组 | 链表 |
|---|---|---|
| 随机访问 | O(1) | O(n) |
| 插入头/尾 | 尾 O(1) / 头 O(n) | O(1) |
| 插入中间 | O(n) | 查 O(n) + 插 O(1) |
| 内存 | 连续 | 不连续 |

### 2. 栈 vs 队列
- **栈**：LIFO 后进先出（递归、撤销）
- **队列**：FIFO 先进先出（BFS、消息队列）
- Java：`Deque` 既能当栈又能当队列（推荐用 `ArrayDeque`）

### 3. 哈希表 ⭐⭐⭐
- 平均 O(1) 增删查
- 冲突解决：**拉链法**（HashMap）/ 开放寻址法
- **刷题神器**：超过 70% 的中等题哈希表能简化

### 4. 堆 ⭐⭐⭐
- 完全二叉树，满足堆有序（大顶/小顶）
- 用数组存储（父 i，左子 2i+1，右子 2i+2）
- **应用**：Top K、优先队列、堆排序
- Java：`PriorityQueue`（默认小顶堆）

### 5. 树 ⭐⭐⭐
- **二叉树**：每个节点最多 2 子
- **二叉搜索树 BST**：左 < 根 < 右
- **平衡二叉树 AVL**：自平衡
- **红黑树**：近似平衡（HashMap、TreeMap）
- **B+ 树**：MySQL 索引（叶子链表相连）
- **Trie 字典树**：前缀匹配

### 6. 图
- **存储**：邻接矩阵（稠密图）/ 邻接表（稀疏图）
- **遍历**：BFS / DFS
- **最短路径**：Dijkstra、Floyd
- **拓扑排序**：检测环 / 安排课程
- **并查集**：连通性问题

### 7. 各结构对应 Java API
| 结构 | Java |
|---|---|
| 动态数组 | ArrayList |
| 链表 | LinkedList |
| 栈/队列 | ArrayDeque |
| 哈希表 | HashMap / HashSet |
| 有序 Map | TreeMap |
| 堆 | PriorityQueue |
| 字符串构造 | StringBuilder |

## 三、排序算法对比 ⭐⭐⭐

| 算法 | 时间 | 空间 | 稳定 | 备注 |
|---|---|---|---|---|
| 冒泡 | O(n²) | O(1) | ✅ | 教学 |
| 选择 | O(n²) | O(1) | ❌ | 教学 |
| 插入 | O(n²) | O(1) | ✅ | 小数据快 |
| **快排** | O(n log n) | O(log n) | ❌ | **生产主流** |
| **归并** | O(n log n) | O(n) | ✅ | 链表常用 |
| **堆排** | O(n log n) | O(1) | ❌ | TopK |
| 桶排序 | O(n+k) | O(n+k) | ✅ | 范围小 |
| 计数排序 | O(n+k) | O(k) | ✅ | 范围小 |

**稳定**：相同元素相对顺序不变。

**面试金句**：
> Java 的 `Arrays.sort` 对基本类型用快排，对对象用 TimSort（归并 + 插入），保证稳定。

## 四、必会算法套路

### 1. 二分查找 ⭐⭐⭐（必背）
```java
int left = 0, right = nums.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;  // 防溢出
    if (nums[mid] == target) return mid;
    else if (nums[mid] < target) left = mid + 1;
    else right = mid - 1;
}
return -1;
```
**关键**：边界（`<=` 还是 `<`，`mid+1` 还是 `mid`），错一个就死循环。

### 2. 双指针 ⭐⭐⭐
- **对撞指针**：左右往中间走（两数之和、回文）
- **快慢指针**：链表环、找中点
- **滑动窗口**：子数组、子串问题

### 3. 滑动窗口模板 ⭐⭐⭐
```java
int left = 0;
for (int right = 0; right < n; right++) {
    // 扩大窗口
    while (条件不满足) {
        // 缩小窗口
        left++;
    }
    // 更新答案
}
```

### 4. DFS / BFS ⭐⭐⭐
**DFS**（递归 / 栈）：
```java
void dfs(状态) {
    if (终止条件) { 处理; return; }
    for (选择 : 所有选择) {
        做选择;
        dfs(新状态);
        撤销选择;  // 回溯
    }
}
```

**BFS**（队列）：
```java
Queue<X> q = new LinkedList<>();
q.offer(起点);
while (!q.isEmpty()) {
    X cur = q.poll();
    for (X next : cur 的邻居) {
        if (没访问过) q.offer(next);
    }
}
```

### 5. 回溯 ⭐⭐⭐
- 本质：DFS + 状态恢复
- 套路：**选择 → 递归 → 撤销选择**
- 题型：排列、组合、子集、N 皇后、数独

### 6. 动态规划 DP ⭐⭐⭐
**三步**：
1. **定义状态**：dp[i] / dp[i][j] 含义
2. **转移方程**：dp[i] 怎么从前面的 dp 算出来
3. **初始化 + 边界**

**经典 5 类**：
- 线性 DP（爬楼梯、最大子数组和）
- 区间 DP（戳气球）
- 背包 DP（0-1 背包、完全背包）
- 字符串 DP（编辑距离、最长公共子序列）
- 树形 DP（打家劫舍 III）

### 7. 贪心
- 每步选当前最优 → 全局最优
- 经典：跳跃游戏、区间调度、分糖果
- **难点**：证明贪心策略正确性（面试不严格证明，能说出来就行）

### 8. 单调栈 / 单调队列 ⭐
- **单调栈**：找下一个更大/更小元素（柱状图最大矩形）
- **单调队列**：滑动窗口最值

### 9. 前缀和 / 差分
- **前缀和**：区间和查询 O(1)
- **差分**：区间修改 O(1)
- 二维前缀和：子矩阵和

### 10. 位运算技巧
- `x & (x-1)`：消除最低位 1
- `x & -x`：取最低位 1
- `异或`：找出现一次的数（其他出现两次）
- `x | (1 << k)`：第 k 位置 1
